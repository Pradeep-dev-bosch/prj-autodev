# Triage (shared knowledge base)

Users run the **TriageAgent** only. Maintainers build/refresh the knowledge once.

## Layout
- `knowledge/component-map.json` – approved components, exact Sub-Delivery values, repos, keywords, thresholds (**fill in the template**).
- `knowledge/generic-signals.json` – noisy tags to ignore.
- `knowledge/signature-index.json` – generated by `build_knowledge.py`.
- `signals.py` – log/ticket signal extraction (tags, processes, packages, libs, AIDL).
- `scorer.py` – scoring, confidence, decision thresholds.
- `triage_cli.py` – what the agent calls. Never writes to Jira.
- `build_knowledge.py` – manifest + source scan + optional historical tickets.
- `tests/test_triage.py` – `python core/triage/tests/test_triage.py`

## Maintainer setup
0. Mapping Excel → map: `python core/triage/import_mapping.py --xlsx <MasterList.xlsx> [--write]` (dry-run by default; keeps keywords/repos; reports case/spelling conflicts instead of merging).
1. Edit `knowledge/component-map.json` (add `repos` / `path_prefixes` per component).
2. `python core/triage/build_knowledge.py --manifest <manifest.xml> --source-root <checkout> --reset`
3. Optional: `--history history.json` with `[{"key","sub_delivery","text"}]` (validated tickets).
4. Refresh a subset: `--only-repos <manifest path> ...`

Decision values: `high_confidence`, `needs_human_review`, `low_confidence_no_change`, `no_match`. Every Jira write requires explicit human approval regardless of decision.
